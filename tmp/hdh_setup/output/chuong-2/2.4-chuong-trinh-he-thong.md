# 2.4. Các chương trình hệ thống

Nguồn chính: **W02 slide 42–43**. Slide 43 liệt kê các nhóm và tên công cụ; định nghĩa ngắn bên dưới giúp nhận diện đúng thuật ngữ.

## Khái niệm chính

Chương trình hệ thống (system program) cung cấp công cụ/môi trường hỗ trợ sử dụng và phát triển chương trình. Người dùng chủ yếu làm việc qua chúng, thay vì thao tác trực tiếp với lời gọi hệ thống (system call).

| Công cụ/nhóm (English) | Dấu hiệu nhận biết |
|---|---|
| Quản lý tập tin (file management) | Tạo, xóa, đổi tên, liệt kê file; slide nêu create, delete, rename, list. |
| Thông tin trạng thái (status information) | Xem ngày/giờ, lượng bộ nhớ trống và thông tin trạng thái hệ thống. |
| Trình soạn thảo (editor) | Soạn thảo/sửa nội dung file. |
| Trình biên dịch (compiler) | Dịch chương trình nguồn thành mã đích. |
| Trình hợp dịch (assembler) | Dịch hợp ngữ (assembly) thành mã máy/mã đối tượng. |
| Trình thông dịch (interpreter) | Thực hiện chương trình bằng cách thông dịch các lệnh. |
| Trình nạp (loader) | Nạp chương trình để chuẩn bị thực thi. |
| Trình tìm lỗi (debugger) | Hỗ trợ tìm lỗi, theo dõi việc thực thi chương trình. |
| Công cụ giao tiếp (communication) | Slide lấy ví dụ email, talk, web browser. |

## Dễ nhầm

- Dịch chương trình → trình biên dịch (compiler); dịch hợp ngữ → trình hợp dịch (assembler); thông dịch/thực hiện lệnh → trình thông dịch (interpreter).
- Nạp chương trình → `loader`; tìm lỗi → `debugger`; sửa nội dung file → `editor`.
- Lời gọi hệ thống (system call) là giao diện yêu cầu dịch vụ; chương trình hệ thống (system program) là công cụ người dùng sử dụng. Không trả lời system call khi câu hỏi đang mô tả compiler hoặc debugger.
- Một công cụ có thể được gọi khác nhau tùy ngữ cảnh. Chương 1 dùng compiler làm ví dụ chương trình ứng dụng trong mô hình các thành phần; mục này xếp compiler vào nhóm công cụ hỗ trợ ngôn ngữ của chương trình hệ thống. Khi câu hỏi hỏi theo phân loại của slide nào, bám ngữ cảnh slide đó.
